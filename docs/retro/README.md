# Retrospectives

One file per sprint: `sprint-1.md`, `sprint-2.md` and so on. A retro looks at how we worked, not at what we built, and ends in a few concrete changes for the next sprint.

## How we hold one

1. Read the actions from the last retro. Did we do them, and did they help?
2. Each of us writes our own points for 5 minutes, without talking.
3. We go through them together: what went well, what did not, what we try next.
4. We pick 1 to 3 actions, each with an owner.
5. The notes go into the sprint's file and close the retro issue.

It is blame-free. We talk about the way we work, not about who did something wrong.

## Template

Copy this into `sprint-N.md`. The facts are filled in from the board before the retro.
